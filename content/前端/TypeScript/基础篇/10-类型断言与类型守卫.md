# 类型断言与类型守卫

## 一、类型断言（Type Assertion）

### 1.1 什么是类型断言？

类型断言是告诉 TypeScript 编译器："**我比你更清楚这个值的类型**"，强制将一个类型视为另一个类型。

```typescript
// 语法：值 as 类型
const value: unknown = 'Hello, TypeScript!'
const length: number = (value as string).length  // ✅

// 尖括号语法（不推荐，与 JSX 冲突）
const length2: number = (<string>value).length
```

> ⚠️ 类型断言只影响编译时类型检查，**不影响运行时行为**，也不做类型转换。

---

### 1.2 常见使用场景

```typescript
// 场景 1：DOM 操作
const input = document.getElementById('username') as HTMLInputElement
input.value = 'Tom'  // ✅ HTMLInputElement 才有 value 属性

// 如果不断言：
const input2 = document.getElementById('username')
// input2.value  // ❌ HTMLElement 没有 value

// 场景 2：API 响应
const data = await response.json() as User
console.log(data.name)  // ✅

// 场景 3：联合类型收窄
type StringOrNumber = string | number
function getLength(val: StringOrNumber): number {
  return (val as string).length ?? (val as number).toString().length
}
```

---

### 1.3 双重断言

当两个类型没有父子关系，无法直接断言时，可以先断言为 `unknown`：

```typescript
// ❌ 不相关的类型无法直接断言
const num = 42 as string   // 报错

// ✅ 通过 unknown 中转（谨慎使用！）
const num2 = 42 as unknown as string

// 实际场景：测试中 mock 数据
interface User { id: number; name: string; email: string }
const mockUser = { id: 1, name: 'Test' } as unknown as User
```

---

### 1.4 非空断言操作符 `!`

```typescript
// 告诉 TS：这个值不是 null 或 undefined
let maybeNull: string | null = getStringOrNull()

// ❌ 可能报错：'string | null' 不能赋值给 'number'
const len: number = maybeNull.length  // maybeNull 可能是 null

// ✅ 非空断言（你确定不是 null）
const len: number = maybeNull!.length

// DOM 中常用
const button = document.querySelector('#submit')!  // 确信元素存在
button.addEventListener('click', handler)
```

> ⚠️ 非空断言 `!` 是危险的，要确保运行时确实不为 null/undefined。

## 二、类型守卫（Type Guards）

类型守卫是一种**运行时检查**，帮助 TypeScript 在特定代码块内**收窄类型**。

---

### 2.1 typeof 类型守卫

```typescript
function process(value: string | number | boolean): string {
  if (typeof value === 'string') {
    // 这里 value 是 string
    return value.toUpperCase()
  } else if (typeof value === 'number') {
    // 这里 value 是 number
    return value.toFixed(2)
  } else {
    // 这里 value 是 boolean
    return value ? 'true' : 'false'
  }
}
```

`typeof` 可以识别：`'string'` | `'number'` | `'boolean'` | `'bigint'` | `'symbol'` | `'object'` | `'function'` | `'undefined'`

---

### 2.2 instanceof 类型守卫

```typescript
class Cat {
  meow() { return '喵~' }
}

class Dog {
  woof() { return '汪!' }
}

function makeSound(animal: Cat | Dog): string {
  if (animal instanceof Cat) {
    // 这里 animal 是 Cat
    return animal.meow()
  } else {
    // 这里 animal 是 Dog
    return animal.woof()
  }
}

// 错误处理中常用
function handleError(error: unknown) {
  if (error instanceof Error) {
    console.error(error.message)  // Error 有 message
  } else if (typeof error === 'string') {
    console.error(error)
  } else {
    console.error('Unknown error:', error)
  }
}
```

---

### 2.3 in 操作符类型守卫

```typescript
interface Bird {
  fly(): void
  layEggs(): void
}

interface Fish {
  swim(): void
  layEggs(): void
}

function move(pet: Bird | Fish): void {
  if ('fly' in pet) {
    // 有 fly 属性 → Bird
    pet.fly()
  } else {
    // 没有 fly 属性 → Fish
    pet.swim()
  }
}

// 更实用的场景
interface Square { kind: 'square'; size: number }
interface Rectangle { kind: 'rectangle'; width: number; height: number }
interface Circle { kind: 'circle'; radius: number }

type Shape = Square | Rectangle | Circle

function describeShape(shape: Shape): string {
  if ('radius' in shape) {
    return `圆形，半径: ${shape.radius}`
  } else if ('size' in shape) {
    return `正方形，边长: ${shape.size}`
  } else {
    return `矩形，${shape.width} × ${shape.height}`
  }
}
```

---

### 2.4 字面量类型守卫

```typescript
type Action =
  | { type: 'ADD'; payload: number }
  | { type: 'SUBTRACT'; payload: number }
  | { type: 'RESET' }

function reducer(state: number, action: Action): number {
  switch (action.type) {
    case 'ADD':
      return state + action.payload  // payload 存在
    case 'SUBTRACT':
      return state - action.payload  // payload 存在
    case 'RESET':
      return 0  // 没有 payload
    default:
      // 穷尽检查
      const _: never = action
      return state
  }
}
```

### 2.5 自定义类型守卫（类型谓词）

使用 `is` 关键字自定义类型守卫函数：

```typescript
// 语法：参数名 is 类型
function isString(value: unknown): value is string {
  return typeof value === 'string'
}

function isUser(obj: unknown): obj is User {
  return (
    typeof obj === 'object' &&
    obj !== null &&
    'id' in obj &&
    'name' in obj &&
    typeof (obj as User).id === 'number' &&
    typeof (obj as User).name === 'string'
  )
}

// 使用
const data: unknown = await fetchData()

if (isUser(data)) {
  // 这里 data 是 User 类型
  console.log(data.name)  // ✅
}

// 数组过滤中非常有用
const values: (string | null | undefined)[] = ['a', null, 'b', undefined, 'c']

// 没有类型守卫，结果类型是 (string | null | undefined)[]
const filtered = values.filter(v => v !== null && v !== undefined)

// 用类型谓词，结果类型精确是 string[]
function isNonNullable<T>(value: T | null | undefined): value is T {
  return value !== null && value !== undefined
}
const strings: string[] = values.filter(isNonNullable)
```

---

### 2.6 断言函数（Assertion Functions）

TypeScript 3.7 引入的特性，让断言函数也能影响类型：

```typescript
// asserts 语法
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== 'string') {
    throw new Error(`Expected string, got ${typeof value}`)
  }
}

function assertIsNonNull<T>(value: T | null | undefined): asserts value is T {
  if (value === null || value === undefined) {
    throw new Error('Expected non-null value')
  }
}

// 使用
let value: unknown = fetchConfig()
assertIsString(value)
// 执行到这里，value 的类型已经是 string
console.log(value.toUpperCase())  // ✅

let user: User | null = getUser()
assertIsNonNull(user)
// 执行到这里，user 肯定不是 null
console.log(user.name)  // ✅
```

## 三、类型收窄（Narrowing）汇总

### 3.1 真值收窄

```typescript
function printMessage(msg: string | null | undefined) {
  if (msg) {
    // msg 是 string（非空、非 null、非 undefined）
    console.log(msg.toUpperCase())
  } else {
    console.log('No message')
  }
}

// 可选链与类型收窄
interface Config {
  server?: {
    host?: string
  }
}

const config: Config = {}
const host = config.server?.host ?? 'localhost'
```

---

### 3.2 相等性收窄

```typescript
function compare(a: string | number, b: string | boolean) {
  if (a === b) {
    // a 和 b 都是 string（两者的公共类型）
    a.toUpperCase()  // ✅
    b.toUpperCase()  // ✅
  }
}

// null/undefined 判断
function foo(x: string | null) {
  if (x === null) {
    // x 是 null
  } else {
    // x 是 string
    console.log(x.length)
  }
}
```

---

### 3.3 控制流分析

TypeScript 会分析控制流，推断每个分支中变量的类型：

```typescript
function example(x: string | number | boolean) {
  if (typeof x === 'string') {
    // x: string
    return x.toUpperCase()
  }

  if (typeof x === 'number') {
    // x: number
    return x * 2
  }

  // x: boolean（其他类型已经 return 了）
  return x ? 'yes' : 'no'
}
```

## 四、综合实战

### 4.1 运行时类型验证库

```typescript
type Validator<T> = (value: unknown) => value is T

// 基础验证器
const isString: Validator<string> = (v): v is string => typeof v === 'string'
const isNumber: Validator<number> = (v): v is number => typeof v === 'number'
const isBoolean: Validator<boolean> = (v): v is boolean => typeof v === 'boolean'

// 组合验证器
function isObject<T extends object>(
  validators: { [K in keyof T]: Validator<T[K]> }
): Validator<T> {
  return (value: unknown): value is T => {
    if (typeof value !== 'object' || value === null) return false
    return Object.entries(validators).every(
      ([key, validator]) => validator((value as any)[key])
    )
  }
}

// 使用
const isUser = isObject<User>({
  id: isNumber,
  name: isString,
  email: isString
})

const data = await response.json()
if (isUser(data)) {
  // data 是 User 类型
}
```

### 4.2 错误处理中的类型守卫

```typescript
class HttpError extends Error {
  constructor(
    public statusCode: number,
    message: string
  ) {
    super(message)
    this.name = 'HttpError'
  }
}

class ValidationError extends Error {
  constructor(
    public field: string,
    message: string
  ) {
    super(message)
    this.name = 'ValidationError'
  }
}

function isHttpError(error: unknown): error is HttpError {
  return error instanceof HttpError
}

function isValidationError(error: unknown): error is ValidationError {
  return error instanceof ValidationError
}

// 使用
try {
  await submitForm()
} catch (error) {
  if (isHttpError(error)) {
    console.error(`HTTP ${error.statusCode}: ${error.message}`)
  } else if (isValidationError(error)) {
    console.error(`Validation failed on ${error.field}: ${error.message}`)
  } else if (error instanceof Error) {
    console.error(`Error: ${error.message}`)
  } else {
    console.error('Unknown error')
  }
}
```

## 五、断言 vs 守卫：选哪个？

| 对比 | 类型断言 `as` | 类型守卫 |
|------|--------------|---------|
| 运行时检查 | ❌ 无 | ✅ 有 |
| 类型安全 | ❌ 较低 | ✅ 高 |
| 代码量 | 少 | 多 |
| 适用场景 | 你确信类型，且无法通过推断获得 | 需要在运行时验证类型 |

**建议优先级**：类型守卫 > 非空断言 `!` > 类型断言 `as`

---

## 总结

- **`as` 断言**：强制指定类型，跳过编译器检查，应谨慎使用
- **`!` 非空断言**：断言值不为 null/undefined
- **`typeof` 守卫**：检查原始类型
- **`instanceof` 守卫**：检查类实例
- **`in` 守卫**：检查属性存在
- **自定义守卫 `is`**：复杂对象结构的类型验证，常用于数组 filter
- **断言函数 `asserts`**：断言后影响后续类型推断
