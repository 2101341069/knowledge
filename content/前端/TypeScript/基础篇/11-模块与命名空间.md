# 模块与命名空间

## 一、模块基础

### 1.1 什么是模块？

在 TypeScript 中，任何包含顶级 `import` 或 `export` 语句的文件都被视为**模块**。没有这些语句的文件被视为**脚本**（全局作用域）。

```typescript
// utils.ts（模块：有 export）
export function add(a: number, b: number): number {
  return a + b
}

// global.ts（脚本：没有 export/import）
// 内容属于全局作用域，会污染全局命名空间
let count = 0
```

---

### 1.2 导出（Export）

```typescript
// === 命名导出 ===

// 1. 声明时导出
export interface User {
  id: number
  name: string
}

export type ID = string | number

export const DEFAULT_USER: User = { id: 0, name: 'Guest' }

export function formatUser(user: User): string {
  return `#${user.id} ${user.name}`
}

export class UserService {
  getAll(): User[] { return [] }
}

// 2. 统一导出
interface Config { host: string; port: number }
const defaultConfig: Config = { host: 'localhost', port: 3000 }
function createServer(config: Config) {}

export { Config, defaultConfig, createServer }

// 3. 重命名导出
export { createServer as startServer }
```

---

### 1.3 默认导出（Default Export）

```typescript
// user.ts
export default class User {
  constructor(public name: string, public age: number) {}
  
  toString() {
    return `${this.name} (${this.age})`
  }
}

// utils.ts
export default function(value: number): string {
  return value.toFixed(2)
}

// config.ts
const config = { host: 'localhost', port: 3000 }
export default config
```

---

### 1.4 导入（Import）

```typescript
// 命名导入
import { User, formatUser, UserService } from './user'

// 重命名导入
import { formatUser as displayUser } from './user'

// 全部导入（命名空间导入）
import * as UserUtils from './user'
UserUtils.formatUser(user)

// 默认导入
import User from './user'
import formatNumber from './utils'

// 混合导入
import User, { UserService, formatUser } from './user'

// 仅类型导入（推荐！）
import type { User, ID } from './user'
// 编译后完全移除，不会产生运行时依赖
```

---

### 1.5 `import type` 的重要性

```typescript
// ✅ 推荐：类型专用导入
import type { User } from './models'

// 好处：
// 1. 编译后彻底移除，不产生运行时代码
// 2. 明确区分类型依赖和值依赖
// 3. 避免循环依赖问题

// 混合：只有 User 是类型
import { type User, UserService } from './models'
```

## 二、模块组织最佳实践

### 2.1 桶文件（Barrel File）

使用 `index.ts` 统一导出，简化导入路径：

```typescript
// models/user.ts
export interface User { id: number; name: string }
export class UserService {}

// models/product.ts
export interface Product { id: number; name: string; price: number }
export class ProductService {}

// models/index.ts（桶文件）
export * from './user'
export * from './product'
export type { User } from './user'  // 仅导出类型

// 使用：一行导入所有
import { User, UserService, Product } from './models'
// 而不是：
// import { User } from './models/user'
// import { Product } from './models/product'
```

---

### 2.2 循环依赖处理

```typescript
// ❌ 循环依赖
// a.ts
import { B } from './b'
export class A { b: B }

// b.ts
import { A } from './a'
export class B { a: A }

// ✅ 解决：提取共同类型
// types.ts
export interface IUser { id: number }

// a.ts
import type { IUser } from './types'
export class UserManager {}

// b.ts
import type { IUser } from './types'
export class UserFormatter {}
```

## 三、模块解析策略

### 3.1 相对路径 vs 非相对路径

```typescript
// 相对路径：相对于当前文件
import { util } from './utils'           // 同级
import { config } from '../config'       // 上级
import { types } from './types/index'    // 子目录

// 非相对路径：从 node_modules 查找
import React from 'react'
import axios from 'axios'
import _ from 'lodash'
```

---

### 3.2 路径别名配置

```json
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@components/*": ["src/components/*"],
      "@utils/*": ["src/utils/*"],
      "@types/*": ["src/types/*"]
    }
  }
}
```

```typescript
// 使用路径别名
import { Button } from '@components/Button'
import { formatDate } from '@utils/date'
import type { User } from '@types/user'

// 而不是
import { Button } from '../../../components/Button'
```

## 四、命名空间（Namespace）

### 4.1 基本概念

命名空间是 TypeScript 独有的特性，用于**组织代码**，避免命名冲突。在现代项目中，模块系统已经解决了这个问题，命名空间主要用于遗留代码和声明文件。

```typescript
// 定义命名空间
namespace Validation {
  // 命名空间内的类型和值
  export interface StringValidator {
    isAcceptable(s: string): boolean
  }

  export class LettersOnlyValidator implements StringValidator {
    isAcceptable(s: string): boolean {
      return /^[A-Za-z]+$/.test(s)
    }
  }

  export class ZipCodeValidator implements StringValidator {
    isAcceptable(s: string): boolean {
      return /^\d{5}$/.test(s)
    }
  }
}

// 使用
const validator = new Validation.LettersOnlyValidator()
validator.isAcceptable('hello')  // true
```

---

### 4.2 命名空间嵌套

```typescript
namespace App {
  export namespace Models {
    export interface User {
      id: number
      name: string
    }
  }

  export namespace Services {
    export class UserService {
      getUser(id: number): Models.User {
        return { id, name: 'Tom' }
      }
    }
  }

  export namespace Utils {
    export function formatUser(user: Models.User): string {
      return `${user.name}(#${user.id})`
    }
  }
}

// 使用
const service = new App.Services.UserService()
const user = service.getUser(1)
console.log(App.Utils.formatUser(user))
```

---

### 4.3 命名空间合并

同名命名空间会自动合并：

```typescript
namespace Animal {
  export interface Legged { legs: number }
  export class Dog {}
}

namespace Animal {
  export interface Swimming { swimSpeed: number }
  export class Fish {}
}

// 合并后
// Animal.Legged
// Animal.Swimming
// Animal.Dog
// Animal.Fish
```

---

### 4.4 命名空间 vs 模块

| 对比 | 命名空间 | 模块 |
|------|----------|------|
| 作用范围 | 编译后是全局对象 | 文件级别 |
| 加载方式 | `<script>` 标签顺序加载 | `import/export` |
| 适用场景 | 纯浏览器、无构建工具 | 现代项目（Node/构建工具） |
| 推荐程度 | 遗留项目 | ✅ 现代推荐 |

> 💡 在使用 webpack/vite 等构建工具的现代项目中，应使用 **ES 模块**而非命名空间。

## 五、声明合并

### 5.1 接口声明合并

```typescript
// 可以分散在不同文件中声明同名接口
interface Window {
  myCustomProperty: string
}

interface Window {
  anotherProperty: number
}

// 合并后
// window.myCustomProperty  // ✅
// window.anotherProperty   // ✅
```

---

### 5.2 模块扩充（Module Augmentation）

```typescript
// 扩展第三方库的类型
// express.d.ts
import 'express'

declare module 'express' {
  interface Request {
    user?: {
      id: string
      roles: string[]
    }
  }
}

// 使用
import { Request, Response } from 'express'

app.get('/profile', (req: Request, res: Response) => {
  // req.user 现在有类型了
  if (req.user) {
    res.json({ id: req.user.id })
  }
})
```

---

### 5.3 全局扩充

```typescript
// 给全局变量添加类型
declare global {
  interface Window {
    __APP_CONFIG__: {
      apiUrl: string
      version: string
    }
  }

  // 全局函数
  function trackEvent(event: string, data?: Record<string, unknown>): void
}

export {}  // 确保文件是模块

// 使用
window.__APP_CONFIG__.apiUrl  // ✅ 有类型
trackEvent('page_view', { path: '/' })  // ✅
```

## 六、三斜线指令（Triple-Slash Directives）

三斜线指令是文件头部的特殊注释，用于声明文件间的依赖关系：

```typescript
/// <reference path="./types.ts" />
/// <reference types="node" />
/// <reference lib="dom" />

// 引用其他文件（不推荐，用 import 代替）
/// <reference path="./utils.ts" />

// 引用 @types 包
/// <reference types="react" />

// 引用内置 lib
/// <reference lib="es2020" />
```

> 💡 在现代 TypeScript 项目中，三斜线指令主要在**声明文件**中使用，日常开发推荐用 `import`。

## 七、动态导入

```typescript
// 懒加载（代码分割）
async function loadChartModule() {
  const { Chart } = await import('./chart')  // 运行时动态加载
  return new Chart()
}

// 按需导入
button.addEventListener('click', async () => {
  const module = await import('./heavyModule')
  module.doExpensiveWork()
})

// 类型安全的动态导入
type ChartModule = typeof import('./chart')
async function getChartClass(): Promise<ChartModule['Chart']> {
  const module = await import('./chart')
  return module.Chart
}
```

## 八、实战：项目模块结构

```
src/
├── types/              # 全局类型定义
│   ├── index.ts        # 桶文件
│   ├── api.ts          # API 相关类型
│   ├── models.ts       # 数据模型类型
│   └── utils.ts        # 工具类型
├── utils/
│   ├── index.ts
│   ├── date.ts
│   └── format.ts
├── services/
│   ├── index.ts
│   ├── user.service.ts
│   └── product.service.ts
└── components/
    └── ...
```

```typescript
// src/types/models.ts
export interface User {
  id: number
  name: string
  email: string
}

export interface Product {
  id: number
  name: string
  price: number
}

// src/types/api.ts
import type { User, Product } from './models'

export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

export type UserResponse = ApiResponse<User>
export type ProductListResponse = ApiResponse<Product[]>

// src/types/index.ts
export type { User, Product } from './models'
export type { ApiResponse, UserResponse, ProductListResponse } from './api'

// 使用（干净清晰）
import type { User, ApiResponse } from '@/types'
```

## 总结

- **ES 模块**是现代 TypeScript 的标准：`import/export`
- **`import type`**：仅导入类型，编译后完全移除
- **桶文件**（barrel）：`index.ts` 统一导出，简化导入路径
- **路径别名**：`tsconfig.json` 的 `paths` 配置，避免相对路径地狱
- **命名空间**：遗留/声明文件用，现代项目用 ES 模块代替
- **模块扩充**：为第三方库补充类型定义
- **动态导入**：懒加载和代码分割
