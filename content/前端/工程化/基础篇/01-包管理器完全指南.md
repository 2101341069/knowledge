# 前端包管理器完全指南

| 特性 | npm v6 | npm v9+ | Yarn v1 | Yarn v4 | pnpm v8 |

#### 2. package.json 字段详解

| 字段 | 说明 | 必填 |
|------|------|-----|
| `name` | 包名，唯一标识符 | ✅ |
| `version` | 语义化版本 | ✅ |
| `main` | CommonJS 入口 | ❌ |
| `module` | ESM 入口 | ❌ |
| `exports` | 导出映射（推荐） | ❌ |
| `types` | TypeScript 类型入口 | ❌ |
| `files` | 发布时包含的文件 | ❌ |
| `bin` | 可执行命令 | ❌ |
| `scripts` | 脚本命令 | ❌ |
| `dependencies` | 生产依赖 | ❌ |
| `devDependencies` | 开发依赖 | ❌ |
| `peerDependencies` | 同伴依赖 | ❌ |
| `engines` | Node 版本要求 | ❌ |

### 依赖版本管理

#### 语义化版本（SemVer）

```
   1.2.3
   │ │ │
   │ │ └── patch  补丁版本（bug 修复）
   │ └──── minor  次版本（新增功能，向下兼容）
   └────── major  主版本（不兼容的 API 变更）
```

#### 版本范围符号

| 符号 | 示例 | 说明 | 匹配版本 |
|------|------|------|---------|
| `^` | `^1.2.3` | 主版本号固定 | 1.2.3 ~ 1.9.9 |
| `~` | `~1.2.3` | 主+次版本固定 | 1.2.3 ~ 1.2.9 |
| `>` | `>1.2.3` | 大于指定版本 | 1.2.4 以上 |
| `>=` | `>=1.2.3` | 大于等于 | 1.2.3 以上 |
| `<` | `<1.2.3` | 小于 | 1.2.2 以下 |
| `<=` | `<=1.2.3` | 小于等于 | 1.2.3 以下 |
| `-` | `1.2.3 - 1.4.5` | 范围 | 1.2.3 ~ 1.4.5 |
| `*` | `*` | 任意版本 | 所有版本 |
| `x` | `1.2.x` | 通配符 | 1.2.0 ~ 1.2.9 |

#### 预发布版本

```json
{
  "dependencies": {
    "alpha": "1.0.0-alpha.1",
    "beta": "2.0.0-beta.3",
    "rc": "3.0.0-rc.1"
  }
}
```

### 锁文件 package-lock.json

```json
{
  "name": "my-project",
  "version": "1.0.0",
  "lockfileVersion": 3,
  "requires": true,
  "packages": {
    "": {
      "name": "my-project",
      "version": "1.0.0",
      "dependencies": {
        "vue": "^3.4.0"
      }
    },
    "node_modules/vue": {
      "version": "3.4.15",
      "resolved": "https://registry.npmjs.org/vue/-/vue-3.4.15.tgz",
      "integrity": "sha512-xxxxx",
      "dependencies": {
        "@vue/compiler-dom": "3.4.15"
      }
    }
  }
}
```

**锁文件作用：**
1. 锁定依赖精确版本，保证团队安装一致性
2. 包含完整性校验（integrity），防止篡改
3. 记录依赖树结构，加速安装过程
4. 避免"在我电脑上好好的"问题

## 三、pnpm 完全指南

### 核心原理：内容寻址存储

```
~/.pnpm-store/              # 全局内容寻址仓库
├── v3/
│   ├── files/              # 按内容 hash 存储的文件
│   │   ├── ab/
│   │   └── cd/
│   └── index.json          # 索引
└── virtual-store/          # 虚拟存储（符号链接）

node_modules/
├── .pnpm/                  # pnpm 内部目录（实际安装位置）
│   └── vue@3.4.15/        # 每个包独立存储
│       └── node_modules/
│           └── vue -> /path/to/store/vue
├── vue -> .pnpm/vue@3.4.15/node_modules/vue  # 符号链接
└── other-package -> .pnpm/other-package@1.0.0/node_modules/other-package
```

**优势：**
- ✅ 所有版本的依赖全局只存一份
- ✅ 相同版本的依赖不会重复安装
- ✅ 节省 50-75% 的磁盘空间
- ✅ 安装速度提升 2-3 倍

### pnpm 特有命令

```bash
# ========== 基础命令 ==========
pnpm install              # 安装依赖
pnpm add package-name     # 添加依赖
pnpm add -D package-name  # 添加 dev 依赖
pnpm remove package-name  # 移除依赖
pnpm update               # 更新依赖

# ========== 独有功能 ==========
pnpm list --recursive     # 递归列出所有包
pnpm why package-name      # 为什么安装了这个包
pnpm store path            # 查看存储路径
pnpm store status          # 查看存储状态
pnpm store prune           # 清理未使用的包

# ========== Monorepo 相关 ==========
pnpm -F <package-name> run <script>  # 过滤执行
pnpm --filter <package-name> run dev  # 同上
pnpm -r run build                     # 递归执行所有包的 build
pnpm -r --parallel run lint           # 并行执行

# ========== 其他 ==========
pnpm env use --global 18     # 切换 Node.js 版本
pnpm dlx package-name         # 临时执行包（不安装）
pnpm dlx create-vite@latest
pnpm exec <command>           # 在项目 context 执行命令
pnpm create vite              # 创建项目
```

### pnpm-workspace.yaml（Monorepo）

```yaml
packages:
  # 所有在 apps/ 下的包
  - 'apps/*'
  # 所有在 packages/ 下的包
  - 'packages/*'
  # 排除测试目录
  - '!**/test/**'
  # 排除示例目录
  - '!examples/*'

# 可选配置
catalog:
  vue: ^3.4.0
  typescript: ^5.3.0
```

## 四、Yarn 指南

### Yarn Berry（v4+）核心特性

```bash
# 启用 Zero Install
yarn install

# .yarnrc.yml
nodeLinker: pnp          # Plug'n'Play（推荐）
# nodeLinker: node-modules  # 传统模式
# nodeLinker: pnpm            # pnpm 模式

yarnPath: .yarn/releases/yarn-4.0.0.cjs
```

### Plug'n'Play（PnP）模式

**传统 node_modules 问题：**
- ❌ 幽灵依赖（未声明但能引入）
- ❌ 嵌套地狱
- ❌ 空间占用大
- ❌ 安装慢

**PnP 解决：**
- ✅ 生成 .pnp.cjs 映射文件
- ✅ 直接从压缩包引用，无需 node_modules
- ✅ 严格依赖检查，无幽灵依赖
- ✅ 安装速度提升 50-100%

```bash
# 启用 PnP
yarn set version berry
yarn install
```

### Yarn 常用命令

```bash
yarn install             # 安装依赖
yarn add package-name    # 添加依赖
yarn add -D package-name # dev 依赖
yarn remove package-name # 移除
yarn up package-name     # 更新
yarn up package-name@1.2.3

yarn dlx package-name    # 临时执行
yarn exec <command>      # 执行

yarn workspaces list     # 列出 workspace
yarn workspace <name> run build
yarn workspaces foreach run build
```

## 五、最佳实践

### 1. 依赖分类原则

| 依赖类型 | 使用场景 | 示例 |
|---------|---------|------|
| **dependencies** | 生产环境必需，运行时代码 | Vue, React, axios, lodash |
| **devDependencies** | 仅开发/构建需要 | Vite, ESLint, TypeScript, Vitest |
| **peerDependencies** | 需要宿主环境提供的依赖 | 组件库中的 Vue/React |
| **optionalDependencies** | 可选，不影响主流程 | fsevents（仅 macOS） |

### 2. 锁文件最佳实践

✅ **提交到 Git：**
- `package-lock.json` (npm)
- `pnpm-lock.yaml` (pnpm)
- `yarn.lock` (yarn)

❌ **不要手动编辑锁文件**
- 只能通过包管理器命令自动更新
- 冲突时执行 `pnpm install` 自动修复，不要手动合并

### 3. 安全实践

```bash
# 检查安全漏洞
npm audit
pnpm audit
yarn npm audit

# 自动修复可修复的漏洞
npm audit fix
pnpm audit fix
```

```json
{
  "scripts": {
    "preinstall": "npx only-allow pnpm"  # 强制使用 pnpm
  }
}
```

### 4. 常见问题排查

**问题 1: node_modules 损坏**
```bash
rm -rf node_modules package-lock.json
npm install
```

**问题 2: 依赖冲突**
```bash
npm ls package-name  # 查看依赖树
pnpm why package-name # 分析为什么安装
```

**问题 3: 安装慢**
```bash
# 切换国内镜像
npm config set registry https://registry.npmmirror.com/
pnpm config set registry https://registry.npmmirror.com/

# 验证
npm config get registry
```

## 六、npx / dlx 详解

### 执行一次性命令

```bash

npx create-vite@latest my-project
pnpm dlx create-vite@latest my-project

# 执行本地 node_modules 中的命令
npx vite build  # 等价于 ./node_modules/.bin/vite build

# 执行指定版本

```
