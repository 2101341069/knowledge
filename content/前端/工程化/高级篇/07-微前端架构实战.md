# 微前端架构实战 - 从概念到落地

## 一、微前端核心概念

### 1.1 什么是微前端？

微前端是一种架构风格，将**独立交付**的前端应用组成一个**更大的整体**。借鉴了后端微服务的理念。

**核心价值：**

| 特性 | 说明 |
|------|------|
| ✅ **独立部署** | 每个微应用独立构建、独立发布、独立运行 |
| ✅ **技术栈无关** | 主应用不限制子应用技术栈（Vue/React/Angular/老项目） |
| ✅ **独立开发** | 团队自治，各自负责自己的业务域 |
| ✅ **增量升级** | 老系统可以渐进式迁移，无需重写 |
| ✅ **独立运行时** | 应用之间状态隔离，互不影响 |

---

### 1.2 主流微前端方案对比

| 方案 | 原理 | 优点 | 缺点 | 推荐度 |
|------|------|------|------|-------|
| **Module Federation** | Webpack 5 内置，运行时共享 | 最优雅，真正的运行时集成 | 强依赖 Webpack 5 | ⭐⭐⭐⭐⭐ |
| **qiankun** | single-spa + HTML Entry | 成熟，开箱即用 | 样式/JS 沙箱开销 | ⭐⭐⭐⭐ |
| **iframe** | 浏览器原生隔离 | 最简单，彻底隔离 | 用户体验差，通信难 | ⭐⭐ |
| **EMP** | 基于 MF 封装 | 功能丰富 | 生态较小 | ⭐⭐⭐ |
| **路由分发** | Nginx 按路径跳转 | 最简单 | 页面刷新，体验差 | ⭐⭐ |

## 二、Module Federation（Webpack 5）实战

### 2.1 核心概念

```
┌─────────────────────────────────────────────────────┐
│                    Host (主应用)                       │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐            │
│  │  App 1   │  │  App 2   │  │  App 3   │            │
│  │ (Remote) │  │ (Remote) │  │ (Remote) │            │
│  └──────────┘  └──────────┘  └──────────┘            │
└─────────────────────────────────────────────────────┘
```

**术语：**
- **Host** - 宿主应用，加载其他应用
- **Remote** - 远程应用，被其他应用加载

---

### 2.2 基础配置（Vue 3 示例）

#### 远程应用（Remote - 子应用）

```javascript
// apps/sub-app/vue.config.js
const { ModuleFederationPlugin } = require('webpack').container

module.exports = {
  publicPath: 'auto',  // ⭐ 关键！自动处理路径
  
  configureWebpack: {
    plugins: [
      new ModuleFederationPlugin({
        // 应用名称（唯一标识）
        name: 'subApp',
        
        // 入口文件名（远程加载的入口）
        filename: 'remoteEntry.js',
        
        // ⭐ 暴露给外部的模块
        exposes: {
          './App': './src/App.vue',
          './components/Button': './src/components/Button.vue',
          './utils': './src/utils'
        },
        
        // ⭐ 共享依赖（避免重复加载）
        shared: {
          vue: {
            singleton: true,     // 单例模式（全局唯一）
            requiredVersion: '^3.3.0'
          },
          'vue-router': {
            singleton: true
          },
          pinia: {
            singleton: true
          }
        }
      })
    ]
  },
  
  // 开发服务器端口
  devServer: {
    port: 8081,
    headers: {
      'Access-Control-Allow-Origin': '*'  // ⭐ 允许跨域
    }
  }
}
```

#### 子应用入口调整

```javascript
// apps/sub-app/src/main.js
import { createApp } from 'vue'
import App from './App.vue'

// ⭐ 独立运行时挂载
if (process.env.STANDALONE) {
  createApp(App).mount('#app')
}

// ⭐ 导出给 Host 使用
export { App }
export { mount, unmount } from './lifecycle'
```

---

#### 宿主应用（Host - 主应用）

```javascript
// apps/host/vue.config.js
const { ModuleFederationPlugin } = require('webpack').container

module.exports = {
  configureWebpack: {
    plugins: [
      new ModuleFederationPlugin({
        name: 'host',
        
        // ⭐ 声明要加载的远程应用
        remotes: {
          // 子应用 1
          subApp: 'subApp@http://localhost:8081/remoteEntry.js',
          
          // 子应用 2（React）
          reactApp: 'reactApp@http://localhost:8082/remoteEntry.js'
        },
        
        // ⭐ 同样要配置共享依赖
        shared: {
          vue: {
            singleton: true,
            requiredVersion: '^3.3.0'
          }
        }
      })
    ]
  }
}
```

---

#### 主应用中使用远程模块

```vue
<!-- apps/host/src/views/SubApp.vue -->
<template>
  <div>
    <h1>加载远程 Vue 应用</h1>
    
    <!-- 直接使用远程组件 -->
    <RemoteButton @click="handleClick" />
    
    <!-- 加载整个远程 App -->
    <component :is="remoteApp" />
  </div>
</template>

<script setup>
import { defineAsyncComponent, ref } from 'vue'

// ⭐ 异步加载远程组件（推荐！）
const RemoteButton = defineAsyncComponent(() => 
  import('subApp/Button')
)

// 加载整个应用
const remoteApp = ref(null)

async function loadRemoteApp() {
  // 动态 import 远程模块
  const module = await import('subApp/App')
  remoteApp.value = module.default
}

loadRemoteApp()
</script>
```

## 三、qiankun 实战（阿里开源方案）

### 3.1 主应用（基座）配置

```bash
# 安装 qiankun
npm i qiankun
```

```typescript
// main-app/src/main.ts
import { registerMicroApps, start } from 'qiankun'
import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')

// ⭐ 注册微应用
registerMicroApps([
  {
    name: 'vueApp',              // 应用名称（唯一）
    entry: '//localhost:8081',   // 子应用地址
    container: '#sub-app-container',  // 挂载容器
    activeRule: '/vue',          // 路由匹配规则
    
    // 传递给子应用的数据
    props: {
      basePath: '/vue',
      userInfo: { name: 'Admin' },
      globalState: {}
    }
  },
  {
    name: 'reactApp',
    entry: '//localhost:8082',
    container: '#sub-app-container',
    activeRule: '/react'
  }
], {
  // 生命周期钩子
  beforeLoad: app => {
    console.log('加载应用:', app.name)
    // 显示 loading
  },
  beforeMount: [app => console.log('即将挂载:', app.name)],
  afterMount: [app => console.log('已挂载:', app.name)],
  beforeUnmount: [app => console.log('即将卸载:', app.name)],
  afterUnmount: [app => console.log('已卸载:', app.name)]
})

// 🚀 启动 qiankun
start({
  prefetch: true,              // 预加载
  sandbox: {
    strictStyleIsolation: true,  // 严格样式隔离（Shadow DOM）
    // experimentalStyleIsolation: true  // 实验性样式隔离
  },
  singular: true,              // 同一时间只显示一个微应用
  excludeAssetFilter: assetUrl => {
    // 过滤某些不需要处理的资源
    return assetUrl.includes('ignore')
  }
})
```

### 3.2 Vue 子应用配置

```typescript
// sub-app-vue/src/main.ts
import { createApp } from 'vue'
import { createRouter, createWebHistory } from 'vue-router'
import App from './App.vue'
import routes from './router'

let router = null
let app = null

// ⭐ 渲染函数（供 qiankun 调用）
function render(props = {}) {
  const { container, basePath } = props
  
  router = createRouter({
    history: createWebHistory(basePath),  // 使用传入的 base
    routes
  })
  
  app = createApp(App)
  app.use(router)
  
  // 挂载到容器中（注意选择器！）
  app.mount(container ? container.querySelector('#app') : '#app')
}

// ⭐ 独立运行时直接渲染
if (!window.__POWERED_BY_QIANKUN__) {
  render()
}

// ⭐ qiankun 生命周期导出
export async function bootstrap() {
  console.log('vue app bootstraped')
}

export async function mount(props) {
  console.log('vue app mount', props)
  render(props)
  
  // 接收主应用传递的数据
  props.onGlobalStateChange((state, prev) => {
    console.log('全局状态变化:', state, prev)
  })
}

export async function unmount() {
  console.log('vue app unmount')
  app.unmount()
  app = null
  router = null
}

export async function update(props) {
  console.log('vue app update', props)
}
```

**webpack 配置（vue.config.js）：**

```javascript
const { defineConfig } = require('@vue/cli-service')

module.exports = defineConfig({
  publicPath: '/',  // 或 'auto'
  
  devServer: {
    port: 8081,
    headers: {
      'Access-Control-Allow-Origin': '*'  // 必须！允许跨域
    },
    historyApiFallback: true
  },
  
  configureWebpack: {
    output: {
      // ⭐ 必须配置，让 qiankun 能获取到导出
      library: 'vueApp',
      libraryTarget: 'umd',
      chunkLoadingGlobal: 'webpackJsonp_vueApp'
    }
  }
})
```

### 3.4 全局状态通信

```typescript
// main-app/src/store/global.ts
import { initGlobalState } from 'qiankun'

// 初始化全局状态
const initialState = {
  user: { name: 'admin', role: 'admin' },
  token: 'xxx',
  theme: 'light'
}

const actions = initGlobalState(initialState)

// 监听状态变化
actions.onGlobalStateChange((state, prev) => {
  console.log('主应用监听到状态变化:', state, prev)
})

// 提供给业务使用的 API
export const globalStore = {
  getState: () => initialState,
  
  setState: (newState) => {
    actions.setGlobalState(newState)
  },
  
  subscribe: (callback) => {
    actions.onGlobalStateChange(callback)
  },
  
  off: () => {
    actions.offGlobalStateChange()
  }
}
```

**子应用中使用：**

```typescript
// sub-app/src/main.ts
export async function mount(props) {
  // 监听全局状态
  props.onGlobalStateChange((state, prev) => {
    console.log('子应用收到状态变更:', state)
  })
  
  // 修改全局状态（会通知所有应用）
  props.setGlobalState({
    theme: 'dark'
  })
}
```

## 四、微前端关键技术问题

### 4.1 样式隔离

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **CSS 前缀** | 每个应用加前缀：.app1-btn | 简单 | 需要约束，有遗漏风险 |
| **CSS Modules** | 构建时生成唯一 hash | 自动化 | 只覆盖局部样式 |
| **Shadow DOM** | 浏览器原生隔离 | 彻底隔离 | 兼容性坑，样式不穿透 |
| **qiankun 沙箱** | runtime 动态处理样式 | 无侵入 | 性能开销 |

**最佳实践：CSS Modules + BEM 命名规范**

```less
// app1 中的样式
.app1-container {
  &__header {
    color: red;
  }
  &__content {
    padding: 16px;
  }
}
```

---

### 4.2 JS 沙箱（避免全局变量污染）

qiankun 内置三种沙箱：

1. **快照沙箱**（SnapshotSandbox）- 兼容 IE
   - 记录 window 快照，卸载时恢复
   - 性能开销大

2. **代理沙箱**（ProxySandbox）- 现代浏览器
   - 用 Proxy 代理 window
   - 子应用读写的都是代理对象

3. **LegacySandbox** - 兼容模式

```typescript
// qiankun 自动启用，无需手动配置
start({
  sandbox: true  // 启用 JS 沙箱（默认 true）
})
```

## 六、部署策略

### 6.1 独立部署（推荐）

```
# 部署结构：
main.example.com          → 主应用
main.example.com/vue/*    → 代理到 Vue 子应用
main.example.com/react/*  → 代理到 React 子应用

# 或者各自独立域名：
main.example.com
vue-app.example.com
react-app.example.com
```

**Nginx 配置：**

```nginx
server {
    listen 80;
    server_name main.example.com;
    root /var/www/main;
    
    # 主应用
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    # Vue 子应用 - 代理转发
    location /vue/ {
        proxy_pass http://vue-app.example.com/;
        proxy_set_header Host $host;
    }
    
    # React 子应用
    location /react/ {
        proxy_pass http://react-app.example.com/;
    }
}
```

---

### 6.2 同域名不同路径

```
example.com/          → 主应用
example.com/vue       → Vue 子应用
example.com/react     → React 子应用
```


## 七、常见问题与解决方案

### Q1：子应用静态资源 404？

**原因：** 子应用的 publicPath 配置错误。

**解决：**

```javascript
// vue.config.js
module.exports = {
  publicPath: process.env.NODE_ENV === 'production' 
    ? '//cdn.example.com/vue-app/'  // 生产环境绝对路径
    : '/'                           // 开发环境
}
```

---

### Q2：主应用和子应用的 Vue 实例重复？

**解决：**

1. **方式一：CDN External**（推荐）
   - 所有应用都从 window.Vue 获取

2. **方式二：Module Federation shared**
   ```javascript
   shared: {
     vue: { singleton: true }
   }
   ```

3. **方式三：主应用传入**
   ```typescript
   // 主应用
   props: { Vue }
   
   // 子应用
   window.Vue = props.Vue
   ```

---

### Q3：主子应用通信最佳实践？

| 场景 | 推荐方案 |
|------|---------|
| 简单通信 | props 传递 + CustomEvent |
| 全局状态 | qiankun globalState / Pinia 共享 |
| 复杂通信 | Event Bus（mitt） / RxJS |

```typescript
// 跨应用通信：CustomEvent
window.dispatchEvent(new CustomEvent('user:login', {
  detail: { userId: 123 }
}))

// 监听
window.addEventListener('user:login', e => {
  console.log(e.detail)
})
```

## 总结

**微前端适用场景：**
- ✅ **大型团队** - 多个团队并行开发，需要技术自治
- ✅ **遗留系统** - 老系统渐进式升级，避免重写
- ✅ **业务中台** - 多个独立业务模块组合成统一产品
- ✅ **多技术栈** - 历史原因导致存在多个技术栈

**微前端不适用场景：**
- ❌ **小型项目** - 技术栈统一，团队规模小，架构复杂度大于收益
- ❌ **强交互应用** - 应用之间频繁通信，沙箱开销大

**技术选型建议：**
- 新项目 → **Module Federation**（最优雅）
- 兼容老项目 → **qiankun**（最成熟）
- 超简单场景 → **iframe**（最省事）
