# 前端监控与性能埋点 - 全链路观测体系

## 一、前端监控体系全景

### 1.1 为什么需要前端监控？

| 问题 | 影响 | 监控解决 |
|------|------|---------|
| 用户遇到白屏/报错 | 流失率上升 | ✅ 异常监控 |
| 页面加载慢 | 体验差、转化低 | ✅ 性能监控 |
| 核心流程中断 | 业务损失 | ✅ 行为埋点 + 链路追踪 |
| 接口请求失败 | 功能不可用 | ✅ 接口监控 |

    timestamp: Date.now(),

app.config.errorHandler = (err, vm, info) => {

    stack: err.stack,
    component: vm?.$options?.name,  // 出错组件

    timestamp: Date.now()
  }
  
  reportError(errorInfo)
}

// ========== 4. React 错误边界 ==========
class ErrorBoundary extends React.Component {
  componentDidCatch(error, errorInfo) {
    reportError({
      type: 'react_error',
      message: error.message,
      stack: error.stack,

    })
  }
}

```typescript
// 使用 source-map 库还原错误位置
import { SourceMapConsumer } from 'source-map'

async function parseErrorStack(stack, sourceMapContent) {
  const consumer = await new SourceMapConsumer(sourceMapContent)
  
  // 解析堆栈每一行
  const parsedStack = stack.split('\n').map(line => {
    const match = line.match(/at\s+(.+?)\s+\((.+?):(\d+):(\d+)\)/)
    if (!match) return line
    
    const [, func, file, line, col] = match
    
    // 还原源码位置
    const original = consumer.originalPositionFor({
      line: parseInt(line),
      column: parseInt(col)
    })
    
    return `at ${func} (${original.source}:${original.line}:${original.column})`
  })
  
  return parsedStack.join('\n')
}
```

        timestamp: Date.now(),

      })
    }
  }
}, true)  // 必须是捕获阶段！

### 2.4 接口异常监控

```typescript
// ========== 拦截 Fetch ==========
const originalFetch = window.fetch

window.fetch = async function(...args) {
  const startTime = Date.now()
  const [url, options] = args
  
  try {
    const response = await originalFetch.apply(this, args)
    
    const duration = Date.now() - startTime
    
    // 上报接口调用
    reportApi({
      url,
      method: options?.method || 'GET',
      status: response.status,
      duration,
      success: response.ok
    })
    
    // HTTP 错误也上报
    if (!response.ok) {
      reportError({
        type: 'api_error',
        url,
        status: response.status,
        message: `HTTP ${response.status}`
      })
    }
    
    return response
    
  } catch (error) {
    // 网络错误
    reportError({
      type: 'network_error',
      url,
      message: error.message
    })
    throw error
  }
}

// ========== 拦截 XMLHttpRequest ==========
const originalXHR = window.XMLHttpRequest

window.XMLHttpRequest = function() {
  const xhr = new originalXHR()
  const startTime = Date.now()
  
  xhr.addEventListener('loadend', () => {
    const duration = Date.now() - startTime
    
    reportApi({
      url: xhr.responseURL,
      method: xhr._method,
      status: xhr.status,
      duration
    })
  })
  
  // 拦截 open 方法获取 method
  const originalOpen = xhr.open
  xhr.open = function(method, url) {
    xhr._method = method
    return originalOpen.apply(this, arguments)
  }
  
  return xhr
}
```

## 三、性能监控（Core Web Vitals）

### 3.1 Web Vitals 三大核心指标

| 指标 | 全称 | 说明 | 优秀阈值 |
|------|------|------|---------|
| **LCP** | Largest Contentful Paint | 最大内容绘制 | < 2.5s |
| **FID** | First Input Delay | 首次输入延迟 | < 100ms |
| **CLS** | Cumulative Layout Shift | 累计布局偏移 | < 0.1 |

### 3.2 完整性能采集代码

```typescript
// ========== LCP 最大内容绘制 ==========
function observeLCP() {
  const observer = new PerformanceObserver((entryList) => {
    const entries = entryList.getEntries()
    const lastEntry = entries[entries.length - 1]
    
    reportPerformance({
      type: 'lcp',
      value: lastEntry.startTime,
      element: lastEntry.element?.tagName,
      url: lastEntry.url
    })
  })
  
  observer.observe({ type: 'largest-contentful-paint', buffered: true })
}

// ========== FID 首次输入延迟 ==========
function observeFID() {
  const observer = new PerformanceObserver((entryList) => {
    const firstInput = entryList.getEntries()[0]
    
    reportPerformance({
      type: 'fid',
      value: firstInput.processingStart - firstInput.startTime
    })
  })
  
  observer.observe({ type: 'first-input', buffered: true })
}

// ========== CLS 累计布局偏移 ==========
function observeCLS() {
  let clsValue = 0
  
  const observer = new PerformanceObserver((entryList) => {
    for (const entry of entryList.getEntries()) {
      // 只计算用户非预期的布局偏移（有 recentInputId 的不算）
      if (!entry.hadRecentInput) {
        clsValue += entry.value
      }
    }
    
    reportPerformance({
      type: 'cls',
      value: clsValue
    })
  })
  
  observer.observe({ type: 'layout-shift', buffered: true })
}

// ========== 传统性能指标 ==========
function getNavigationTiming() {
  const timing = performance.timing
  
  const metrics = {
    // DNS 查询
    dns: timing.domainLookupEnd - timing.domainLookupStart,
    
    // TCP 连接
    tcp: timing.connectEnd - timing.connectStart,
    
    // SSL 握手
    ssl: timing.connectEnd - timing.secureConnectionStart,
    
    // 后端响应（TTFB）
    ttfb: timing.responseStart - timing.requestStart,
    
    // 内容下载
    download: timing.responseEnd - timing.responseStart,
    
    // DOM 解析
    domParse: timing.domInteractive - timing.responseEnd,
    
    // 首字节到首屏
    fpt: timing.responseStart - timing.navigationStart,
    
    // DOM Ready
    domReady: timing.domContentLoadedEventEnd - timing.navigationStart,
    
    // 页面完全加载
    load: timing.loadEventEnd - timing.navigationStart
  }
  
  reportPerformance({
    type: 'navigation',
    ...metrics
  })
}

// ========== 资源加载耗时 ==========
function getResourceTiming() {
  const resources = performance.getEntriesByType('resource')
  
  resources.forEach(resource => {
    // 只上报慢资源
    if (resource.duration > 1000) {
      reportPerformance({
        type: 'slow_resource',
        url: resource.name,
        duration: resource.duration,
        transferSize: resource.transferSize,
        initiatorType: resource.initiatorType  // script / css / img
      })
    }
  })
}

// ========== 初始化性能监控 ==========
window.addEventListener('load', () => {
  observeLCP()
  observeFID()
  observeCLS()
  getNavigationTiming()
  
  setTimeout(getResourceTiming, 5000)
})
```

function observeExposure() {
  const observer = new IntersectionObserver((entries) => {
    entries.forEach(entry => {
      // 元素进入视口超过 50%
      if (entry.intersectionRatio >= 0.5) {

### 5.2 批量上报 + 节流

```typescript
class Reporter {
  private queue: any[] = []
  private timer: number | null = null
  private readonly BATCH_SIZE = 20    // 每 20 条上报一次
  private readonly INTERVAL = 5000    // 每 5 秒上报一次
  
  add(data: any) {
    this.queue.push(data)
    
    // 达到批量大小，立即上报
    if (this.queue.length >= this.BATCH_SIZE) {
      this.flush()
    } 
    // 否则启动定时器
    else if (!this.timer) {
      this.timer = window.setTimeout(() => {
        this.flush()
      }, this.INTERVAL)
    }
  }
  
  flush() {
    if (this.queue.length === 0) return
    
    const data = [...this.queue]
    this.queue = []
    
    if (this.timer) {
      clearTimeout(this.timer)
      this.timer = null
    }
    
    // 批量上报
    navigator.sendBeacon('/api/report/batch', JSON.stringify(data))
  }
  
  // 页面关闭前强制上报
  beforeUnload() {
    this.flush()
  }
}

export const reporter = new Reporter()
```

## 总结

**前端监控最佳实践：**

1. **分层上报** - 错误 100% 上报，性能采样上报，行为按需上报
2. **批量上传** - 减少请求数，降低对用户的影响
3. **可靠传输** - 优先 sendBeacon，保证页面关闭也能上报
4. **SourceMap** - 必须配置，不然错误堆栈没法看
5. **用户关联** - 每个上报带上用户 ID，方便排查单个用户问题
6. **环境标识** - 区分生产/测试/预发，避免数据污染

**监控成熟度模型：**
- L1：能看到报错
- L2：能定位问题
- L3：能复现问题
- L4：能预测问题
- L5：能自动修复
