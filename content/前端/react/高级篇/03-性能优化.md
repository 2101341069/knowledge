# React 性能优化

## 一、什么时候需要优化？

> 先不要过早优化！先用 React DevTools Profiler 测量，找到性能瓶颈再针对性优化。

常见性能问题：
- 列表太多，滚动卡顿
- 输入框打字延迟
- 页面切换动画不流畅
- 首次加载太慢

---

## 二、减少不必要的重渲染

### 2.1 React.memo - 组件级缓存

包裹组件，props 没变就不重渲染：

```jsx
// 普通组件：父组件重渲染，子组件跟着重渲染
function Child({ name, age }) {
  return <div>{name} - {age}</div>
}

// ✅ 用 memo 包裹：props 没变就不重渲染
const Child = memo(function Child({ name, age }) {
  return <div>{name} - {age}</div>
})
```

> 💡 memo 是**浅比较**，只比较 props 的引用。对象/数组/函数 props 要配合 useMemo/useCallback 才有效。

---

### 2.2 useMemo - 缓存计算结果

```jsx
function SearchResults({ items, query }) {
  // ❌ 每次渲染都重新过滤，数组大时会卡顿
  // const filteredItems = items.filter(item => item.includes(query))

  // ✅ 只有 items 或 query 变化时才重新计算
  const filteredItems = useMemo(() => {
    return items.filter(item => item.includes(query))
  }, [items, query])

  return (
    <ul>
      {filteredItems.map(item => <li key={item}>{item}</li>)}
    </ul>
  )
}
```

---

### 2.3 useCallback - 缓存函数

```jsx
function Parent() {
  const [count, setCount] = useState(0)

  // ❌ 每次渲染都创建新函数，memo 子组件还是会重渲染
  // const increment = () => setCount(c => c + 1)

  // ✅ 缓存函数，依赖不变时是同一个引用
  const increment = useCallback(() => {
    setCount(c => c + 1)
  }, [])

  return <Child onIncrement={increment} />
}

// 子组件必须用 memo 包裹，否则 useCallback 没用！
const Child = memo(function Child({ onIncrement }) {
  return <button onClick={onIncrement}>+</button>
})
```

---

### 2.4 state 下放

把 state 移动到真正需要它的子组件，避免父组件重渲染影响其他子组件：

```jsx
// ❌ 不好：输入框的状态放在父组件，输入时整个页面都重渲染
function App() {
  const [text, setText] = useState('')
  return (
    <div>
      <input value={text} onChange={e => setText(e.target.value)} />
      <HeavyComponent />  {/* 每次输入都会跟着重渲染！ */}
    </div>
  )
}

// ✅ 好：state 下放给子组件，输入时只重渲染输入框
function SearchInput() {
  const [text, setText] = useState('')
  return <input value={text} onChange={e => setText(e.target.value)} />
}

function App() {
  return (
    <div>
      <SearchInput />
      <HeavyComponent />  {/* 不会受影响 */}
    </div>
  )
}
```

## 三、列表优化

### 3.1 正确使用 key

```jsx
// ❌ 不要用 index 当 key（列表会增删/重排时）
{list.map((item, index) => <li key={index}>{item.name}</li>)}

// ✅ 用稳定唯一的 ID
{list.map(item => <li key={item.id}>{item.name}</li>)}
```

---

### 3.2 虚拟列表（长列表必须用！）

只渲染可视区域内的元素，10000 条列表也不卡：

```bash
pnpm add react-window
```

```jsx
import { FixedSizeList as List } from 'react-window'

function LongList({ items }) {
  const Row = ({ index, style }) => (
    <div style={style}>{items[index].name}</div>
  )

  return (
    <List
      height={400}      // 可视区域高度
      itemCount={items.length}  // 总条数
      itemSize={50}     // 每行高度
      width="100%"
    >
      {Row}
    </List>
  )
}
```

推荐库：
- `react-window` - 轻量
- `react-virtualized` - 功能更全

## 四、懒加载（代码分割）

首屏只加载首屏需要的代码，其他路由/组件按需加载，减少首屏白屏时间。

### 4.1 路由级懒加载

```jsx
import { lazy, Suspense } from 'react'
import { Routes, Route } from 'react-router-dom'

// 动态 import，打包时会分成单独的 chunk
const Home = lazy(() => import('./pages/Home'))
const About = lazy(() => import('./pages/About'))
const Users = lazy(() => import('./pages/Users'))

function App() {
  return (
    // 加载时显示 fallback
    <Suspense fallback={<div className="loading">加载中...</div>}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/users" element={<Users />} />
      </Routes>
    </Suspense>
  )
}
```

---

### 4.2 组件级懒加载

```jsx
// 大组件（如编辑器、图表等）单独懒加载
const HeavyEditor = lazy(() => import('./HeavyEditor'))

function ArticlePage() {
  const [showEditor, setShowEditor] = useState(false)

  return (
    <div>
      <h1>文章</h1>
      <button onClick={() => setShowEditor(true)}>
        打开编辑器
      </button>

      {/* 点击按钮后才加载编辑器代码 */}
      {showEditor && (
        <Suspense fallback={<div>编辑器加载中...</div>}>
          <HeavyEditor />
        </Suspense>
      )}
    </div>
  )
}
```

## 五、数据获取优化

### 5.1 用 React Query/SWR 管理服务端状态

```jsx
import { useQuery } from '@tanstack/react-query'

function UserList() {
  // ✅ 自带：缓存、去重、重试、后台刷新、预加载
  const { data, isLoading, error } = useQuery({
    queryKey: ['users'],
    queryFn: fetchUsers
  })

  if (isLoading) return <div>加载中...</div>
  return <ul>{data.map(user => <li key={user.id}>{user.name}</li>)}</ul>
}
```

好处：
- 相同 key 的请求自动去重，只发一次
- 数据缓存，切页面回来不用重新请求
- 支持预加载、乐观更新等

## 六、其他优化技巧

### 6.1 useTransition - 非阻塞更新

```jsx
function SearchApp() {
  const [query, setQuery] = useState('')
  const [results, setResults] = useState([])
  const [isPending, startTransition] = useTransition()

  function handleChange(e) {
    setQuery(e.target.value)
    // 标记为低优先级更新，输入框不会卡顿
    startTransition(() => {
      setResults(filterBigList(e.target.value))
    })
  }

  return (
    <div>
      <input value={query} onChange={handleChange} />
      {isPending ? '搜索中...' : <List items={results} />}
    </div>
  )
}
```

---

### 6.2 useDeferredValue - 延迟更新不紧急的数据

```jsx
function Search({ query }) {
  // query 变化时，deferredQuery 延迟更新，避免阻塞输入
  const deferredQuery = useDeferredValue(query)
  const results = useMemo(() => search(deferredQuery), [deferredQuery])
  return <List items={results} />
}
```

## 七、性能检测工具

### React DevTools Profiler

1. 打开浏览器开发者工具 → Profiler 标签
2. 点击录制，操作你觉得卡顿的地方
3. 停止录制，看火焰图，找渲染时间长的组件

重点看：
- 哪些组件重渲染了？为什么重渲染？
- 哪个组件渲染时间最长？

---

## 八、优化原则

1. **先测量再优化**，不要瞎优化
2. **优先业务逻辑优化**，再考虑 React API 优化
3. **不要过度优化**，memo/useMemo/useCallback 本身也有开销
4. **提升用户感知**比单纯追求性能指标更重要（加个 loading spinner 比优化 100ms 效果好）

---

## 总结

✅ **减少重渲染**：`React.memo` + `useMemo` + `useCallback`，state 下放
2. ✅ **列表优化**：正确的 key，长列表用虚拟滚动
3. ✅ **代码分割**：`React.lazy` + `Suspense` 路由/组件级懒加载
4. ✅ **数据请求**：用 React Query/SWR 缓存、去重
5. ✅ **并发特性**：`useTransition` / `useDeferredValue` 不阻塞用户输入
6. ✅ **先测量再优化**：用 React DevTools Profiler 找瓶颈
